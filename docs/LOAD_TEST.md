# Ачааллын тест

**Асуулт:** Нэг backend процесс хэдэн оюутныг зэрэг хянаж чадах вэ?

## Арга зүй

`scripts/loadtest/ws_load.py` нь N оюутныг дуурайна. Оюутан бүр:
- 5 fps-ээр 640×360 JPEG кадр илгээнэ (бодит нүүртэй зураг, MediaPipe + YOLO бүрэн ажиллана)
- 2 секунд тутам WebM/Opus дуу илгээнэ
- ~12 секунд тутам client event илгээнэ

Нэг багш холбогдож эхний оюутныг ажиглана. Халаалтын 10 секундийн дараа 40 секундын турш хэмжинэ.

| Хэмжүүр | Утга | Зорилт |
|---|---|---|
| Шинжилгээ/с/оюутан | Сервер оюутан бүрийн кадрыг секундэд хэдэн удаа шинжилсэн | 1.0 |
| p50 / p95 | Нэг кадрын шинжилгээний хугацаа (дараалал хүлээх хугацааг оруулаад) | — |
| Аудио/с/оюутан | Дууны шинжилгээ | 0.5 |
| Event хоцролт | Client event → багшийн самбарт хүрэх хугацаа | < 1с |
| Багш fps | Ажиглаж буй оюутны видео | 5 |

**Орчин:**
- Intel Core i7-12700 (20 thread), 15.7 GB RAM, Windows 11, Python 3.11, CPU (GPU-гүй)
- Ачааллын клиент нь сервертэй нэг машин дээр ажилласан тул үр дүн нь болгоомжтой (доогуур) тооцоо.

## Дүгнэлт

- **≤10 оюутан:** Бүх зорилт хангагдсан. Кадр бүр секундэд 1 удаа шинжлэгдэж, event багшид 0.03 секундэд хүрнэ.
- **20–30 оюутан:** Шинжилгээ секундэд 0.8 орчим болж буурна. Гэхдээ босгууд бодит цагаар тооцогддог тул "5 секунд нүүр алга" гэх мэт утга өөрчлөгдөхгүй, зөвхөн нарийвчлал нь бага зэрэг буурна. Багшийн видео болон event-ийн хоцролт (< 1.5с) хэвийн хэвээр байна.
- **Гацаа:** Нэг кадрын шинжилгээний ~80% нь YOLO. Thread эсвэл процесс нэмэх нь нийт багтаамжийг ~15 кадр/с-ээс дээш өсгөсөнгүй (`AI_WORKERS` 1→4: 11→15 кадр/с; 4 процесс: 15 кадр/с), учир нь YOLO аль хэдийн олон цөм ашигладаг. Тиймээс оюутан тус бүрд ногдох тооцоог багасгах нь хамгийн үр дүнтэй байв.

## Цааш тэлэх
- **Client талын inference:** Нүүр, харцын шинжилгээг browser-т MediaPipe-WASM-аар хийж, серверт зөвхөн event болон YOLO-д зориулсан цөөн кадр илгээнэ.
- **GPU:** YOLO-гийн хугацааг 10 дахин орчим бууруулна.
- **Хэвтээ тэлэлт:** Олон backend процесс ажиллуулж, оюутнуудыг тэдгээрт хуваана. Үүний тулд одоогийн санах ойд хадгалдаг төлөвийг (`_students`, `_teachers`) Redis руу шилжүүлэх шаардлагатай.
